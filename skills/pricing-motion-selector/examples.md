# Pricing Motion Selector Examples

## Example invocation

> Run `pricing-motion-selector` for a self-serve solo-builder decision tool.
>
> Product shape: structured decision skills for solo builders.
> Support burden: low to medium.
> Cost to serve: low if usage is mostly text generation and docs.
> Onboarding complexity: low if the user can start with one skill.
> Buyer type: solo builders paying personally.

## Example output

### Recommended pricing motion
**Free starter skills + paid pro pack or hosted workspace**

### Why it fits
- users can get value quickly from one skill
- self-serve adoption is realistic
- free usage can help discovery if a few core skills are public
- paid value can come from deeper skill packs, saved history, and hosted project continuity

### Why the alternatives are weaker
- **full freemium app:** risky if the hosted layer is thin and users can get enough value from public docs alone
- **free trial only:** too much friction for an early skill library trying to gain adoption
- **paid pilot:** wrong motion; the buyer is usually an individual, not a company with procurement

### Upgrade trigger
A user wants:
- deeper skill packs
- saved project memory
- repeated weekly reviews
- reusable artifact history across projects

### Pricing test plan
- keep 2-3 strong skills free
- package the full decision chain as paid
- test whether users pay more for hosted continuity than for raw markdown alone

## Why this is a good example

It makes one clear recommendation based on product shape and economics instead of blindly defaulting to freemium because that sounds modern.
