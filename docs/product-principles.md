# Product Principles

## Core rule

> Build something narrow, simple, self-evidently useful, and easy to adopt — then find a real distribution loop.

## Product stance

OpenThinking should be a brutal decision system for solo builders.

It should help users answer:
- should I pursue this idea?
- who is it really for?
- what is the wedge?
- what is the smallest MVP?
- how should I price it?
- what GTM channel should I start with?
- should I continue, revise, or kill it?

## Non-goals

Do not turn this repo into:
- a founder operating system
- a note-taking system
- a second brain
- a broad prompt marketplace
- an AI lifestyle brand

## Product unit

The product unit is a named skill that produces a saved artifact.

## Packaging stance

- doctrine can be public
- starter skills can be public
- premium packaging, hosted memory, and deeper skill packs can be paid later

## Scope filter

Reject anything that:
- increases abstraction without increasing usefulness
- delays first value
- adds many shallow skills instead of a few strong ones
- makes adoption harder for a solo builder
